# M3 实施计划 — GitBridge + S3Bridge + 桥工厂

> **For agentic workers:** 按任务顺序执行；每任务以独立提交收尾；全量回归 + tsc 干净是每个任务的完成条件之一。

**Goal:** 交付 ChannelBridge 接口的另外两个实现（GitBridge、S3Bridge）+ 桥选择工厂，使项目在行内 GitLab / 各大云 / 自建 MinIO 上零改造可用。

**Architecture:** 两个新实现各自封装后端原生动作为 Mailbox 语义（seq 计数文件 + 密文对象/文件 + 成员表）；工厂按 env 选择；上层（工具/broadcaster/插件/双游标）零改动。

**Tech Stack:** Bun + node:crypto + 系统 git（GitBridge）+ fetch 手写 SigV4（S3Bridge）。零新依赖。

**Spec:** `docs/superpowers/specs/2026-10-26-m3-backends-design.md`

## Global Constraints

- E2E 不放松：落盘前必 seal，读出后必 open；密文文件名只含 seq/idemKey 前缀
- 竞争重试统一 ≤5 次；耗尽抛可行动错误
- listen = 定时轮询（git 15s / s3 10s 默认，可配）；onNotify 仅唤醒
- env：`SHARE_CONTEXT_BRIDGE=relay|git|s3`、`SHARE_CONTEXT_GIT_REMOTE_ROOT`（git 仓库根 URL）、`SHARE_CONTEXT_S3_ENDPOINT/BUCKET/REGION/AK/SK`
- 全量 `bun test` + `bunx tsc --noEmit` 每任务收尾必须绿/净
- commit message 英文

## Review Focus

1. Git push 竞争：两成员同时 send → 双方消息都在且 seq 不冲突（重试路径真实覆盖）
2. S3 条件写 412 → 重读重试，无静默覆盖
3. rotate 后旧 epoch 消息不再出现于新 poll，但 re-join 后旧钥成员仍可读（epoch 目录隔离）
4. 工厂 env 非法值 → 明确报错而非静默回退 relay
5. 双 Bridge 的 listen 停止后无定时器泄漏
