## 未验证（⏸ 环境受阻，非代码缺陷）

插件的三种注入行为（摘要卡搭便车、@me 紧急 steer、防遗忘提醒）未能在 headless 探针会话中取得直接证据。三个叠加的环境障碍：

1. **MCP 异步连接延迟**（1–2 分钟）：headless 探针任务的 agent 起手时目录中还没有 channel 工具，短任务等不到就结束了（真实交互式会话不受此影响——用户会话远长于探针）
2. **BocomCode 服务器反复重启**（本日 7+ 次）：杀掉了大部分长时探针
3. **stderr 路由**：standalone + json 模式下 server/插件 stderr 不可见，丢失诊断信号

插件逻辑本身有 37 个单测覆盖（coalesce/urgent 旁路/anti-forget 纯函数 + 插件加载 smoke），加载链已被服务器日志证实。注入行为的最终确认建议由用户按 `packages/relay/README.md` checklist 在交互式会话中完成（交互会话无上述 1/2 障碍）。

## 冒烟过程中发现并已修复的问题

1. `packages/plugin-opencode/index.ts` 及 src 内部所有相对导入**缺少 .ts 扩展名**——fork 插件加载器无扩展名补全，导致插件静默加载失败（"failed to load plugin"，ERR_MODULE_NOT_FOUND）。已全部修复并提交
2. spawn 的 stdio server 在客户端关闭后不退出（broadcaster/WS 持有事件循环）→ 已加 stdin end/close + SIGTERM/SIGINT 兜底退出（M1 侧修复）
3. fetch_updates 与 broadcaster 的消费竞争 → delivered/high-water 双游标设计（abe453）
