## 实验目的

验证设计最大假设（spec §8）：**在无人提醒的前提下，AI agent 会在协作任务中自主调用 share/fetch 协作工具**。echo MCP server（`packages/spike/mcp-echo-server.ts`）为纯 no-op（JSONL 日志 + 预置消息），工具描述按产品措辞（`packages/spike/TOOL-PROMPTS.md`）注入。

## 实验流程

1. 两个 opencode 会话（两个独立工作目录），各配 echo server（stdio）；
2. 每组给一对协作任务，两会话同时开工；**全程不口头提醒协作工具**；
3. 10 组：需求方/实现方 5 组、跨模块分工 5 组；每组用与行内场景一致的主力模型；
4. 会话结束后读 `spike-log.jsonl` 记分；不达标 → 只迭代工具描述与 instructions（更新 TOOL-PROMPTS.md），再跑；
5. 迭代轮数不设上限，以指标收敛为准；多轮仍停滞且明显是 agent 能力限制 → 升级主人决策。

## 记分标准（主人已确认）

| 指标 | 定义 | 阈值 |
| --- | --- | --- |
| ① 自主 share 命中率 | 应 share 事件（决策/接口变更/踩坑/里程碑/环境事实/claim）中 agent 自主 `share_update` 的比例 | ≥ 80% |
| ② 动手前自主 fetch 率 | 「任务开始 / 改他人模块前」时机中 agent 自主 `fetch_updates` 的比例 | ≥ 70% |
| ③ 敏感泄漏 | statement 中含凭据/密钥/敏感 PII 的条数 | = 0 |
